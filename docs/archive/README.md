## 从这里搬走时做过的修正

1. **PLAN.md 的交叉引用是错的。** PLAN.md 自己的开头注记与 ADR-003 §0 都写
   「PLAN.md §5 的 MQTT 契约 / §6 服务端 / §7 HA 集成不变」，
   但 PLAN.md 实际只有 §0~§6，且 §5 是分期实施表、§6 是待拍板问题。
   契约与服务端内容真正的位置是 **§4（系统架构图 + 其后的散文）加 §5 分期表的 P2/P3 行**。
   DESIGN.md 按实际位置引用。
2. **ADR-002 §1.6 vs §1.4/§1.7 的 INT1/INT2 矛盾**没有在归档里解决，
   原样带进 DESIGN.md 的待解决表（R2 阶段读 Zephyr 驱动源码定论）。
3. **ADR-002 把 ADR-001 §5.7 整条标成「不适用」时，连带划掉了备份电芯自己的低温充电安全需求**
   （0 °C 以下充电会析锂）。这个文档缺口在 DESIGN.md 里显式记着，
   以免将来重新加电芯时漏掉。
4. **「MQTT 契约三次架构变更一字未改」这个叙事是误导的。** 它从来没有被写下来过：
   全项目可查的契约级字面量只有 `state` / `/track` / `src=lbs` / `accuracy` 四个，
   没有任何 topic 名或 JSON 字段定义。见 DESIGN.md §9.3。
5. **ADR-003 §8 那句「右半边一个字没变」与它自己的图不符**——三份框图的右半边
   实际有 5 处差异（SQLite 节点、retain 回边、TLS 标注等）。见 DESIGN.md §9.1b。
6. **「设备端无缓存无重发」被读成了「报文永久丢失」。** PLAN.md 自己的 P1 行里就有
   `fskv` 补发队列。那句话说的是 LuatOS `mqtt` 库这一层的原语。见 DESIGN.md §9.1。
7. **ADR-001 §3.4「要远程开锁就必须用 PRO」的前提被 ADR-003 抽掉了**——
   开锁已改为完全离线的挑战应答（先是 NFC，2026-09-02 起是 BLE），
   PRO 只剩远程定位一个理由。
   ADR-003 从未重述这个决定，DESIGN.md §8.4 重新回答了它。
8. **ADR-001 §3.7 建议的 Air780EPM 替换在 ADR-003 里一次都没被讨论或否决**，
   处于悬置状态。DESIGN.md §8.6 / §11 #19 把它变成一个有截止点的待决项。
