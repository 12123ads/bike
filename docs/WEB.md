# 网页界面

> 和 HTTP API 共用 `http_bind`（默认 `127.0.0.1:8080`）。
> 打开浏览器访问 `http://127.0.0.1:8080/` 即可。
> ⚠ 它能下发指令（含远程开锁，如果你打开了），**别把 8080 直接摊到公网**。

## 1. 长什么样

左边侧栏 + 右边地图。侧栏从上到下：

| 区块 | 内容 |
| --- | --- |
| 状态徽章 | 在线/离线、移动中/静止、已上锁/未上锁/**未知** |
| 数据表 | 位置（经纬度）、精度、定位方式、电压、电量、围栏、最后上报（相对+绝对时间） |
| 轨迹 | 时间范围下拉（1 小时 ~ 30 天）+「缩放到轨迹」 |
| 指令 | 立刻定位 / 要遥测 / 上锁 / **远程开锁**（默认灰掉） |
| 待确认下行 | 队列里还没送到设备的指令（契约 §4.1） |
| 最近事件 | 30 条，移动/开锁/低电量分色 |

地图上：车的当前位置一个标记 + 一个**误差圈**（半径 = `state.a`），
轨迹一条带方向箭头的折线。底图用高德的暗色样式，和界面配色一致。

## 2. 登录

用**服务端的 API token** 登录（`ebike-server init` 打印过，也在 `config.json` 里）。

**为什么要登录而不是直接用 Bearer**：网页如果用 Bearer，token 就得存在
localStorage 或 JS 变量里，而**它能下发指令**。localStorage 里的东西
任何一个 XSS 都能拿走且长期有效。所以：

- 登录页拿 token 换一个**短期会话 cookie**（默认 12 小时）；
- cookie 是 `HttpOnly`（JS 拿不到）+ `SameSite=strict`（挡 CSRF）；
- **API token 本身不进浏览器存储**；
- 会话存服务端内存，重启就得重新登（单车单用户，这是对的取舍）。

登录接口有限速：同一 IP 5 分钟内失败 10 次就返回 429。
**限速期间连正确的 token 也进不去** —— 否则限速可以被绕过。

⚠ **`cookie_secure` 默认是 `false`**，因为默认部署是 `http://127.0.0.1`，
加了 `Secure` 浏览器就不会回传 cookie，登录会陷入死循环。
**放到 HTTPS 反向代理后面时，把配置里的 `web.cookie_secure` 改成 `true`。**

## 3. 高德 key

放在文件里，默认读 `/root/gaode.key`（内容就是一行 32 位 key）。

```json
"web": {
  "enabled": true,
  "gaode_key_file": "/root/gaode.key",
  "gaode_security_code": "",
  "session_ttl": 43200,
  "cookie_secure": false
}
```

⚠ **Docker 部署要注意权限。** 容器以 uid 1000 跑，而 `/root/gaode.key` 默认是
`0600 root:root` —— 那样挂进去**读不到**（实测：`PermissionError`，网页地图空着）。
两条路：

```bash
# a) 放开读权限（简单）
chmod 644 /root/gaode.key

# b) 或者删掉 compose 里的挂载，用环境变量传
echo "EBIKE_GAODE_KEY=$(cat /root/gaode.key)" >> /opt/ebike-tracker/.env
# 然后在 docker-compose.yml 里取消 EBIKE_GAODE_KEY 那行的注释
```

(a) 是可以接受的：**JS API 的 key 本来就要发给浏览器**（任何用了高德地图的网页
都能在源码里看到它）。真正的保护手段是在高德控制台给这个 key 配**域名白名单**。

读不到 key 时**会在日志里 warn**，且网页会显示一段说明并退化成「只显示经纬度」，
其余功能不受影响。（这条 warn 是补上的 —— 一开始是静默返回空串，
结果容器里因权限读不到时，网页只是地图空着而日志一个字都没有。）

`gaode_security_code` 只有用到需要服务端代理的高德插件才要填，
基础地图 + 标记 + 折线**不需要**，留空即可。

## 4. 坐标系

**实时位置**用服务端算好的 GCJ-02（契约 §7 的 `gla`/`glo`）——
高德底图就是 GCJ-02，前端不做转换。`gla` 缺失时**不回落到 WGS84**：
静默回落会让车偏几百米而界面上看不出异常。

**轨迹**不一样：`/api/track` 返回的是**落库的原始 WGS84**，所以前端要自己转。
前端的转换函数和服务端 `geo.py` 是同一个算法同一套常数 ——
`tests/test_web_frontend.py` 拿 7 个点（含境外）逐个比对，**误差 0 厘米**。
不一致的后果是轨迹整体偏移而实时点是准的，看起来像「轨迹坏了」。

## 5. 远程开锁

服务端 `allow_remote_unlock` 是 false 时，按钮**直接是禁用的**，
下面写明原因。让用户点一下再吃 403 是糟糕的体验。

打开之后按钮可用，但点了会先弹确认框（「会绕过手机 BLE 的挑战应答」）。
网页和 JSON API 走**同一套检查** —— 没有一条路能绕过去，
`test_web_unlock_403_by_default` 钉住了这一点。

## 6. 刷新频率

| 内容 | 间隔 | 为什么 |
| --- | --- | --- |
| `state` | 5 秒 | 服务端自己每 30 秒重算在线状态，但设备上报是随时的。5 秒能让「刚点了立刻定位」几乎马上看到 |
| 事件 + 待确认下行 | 15 秒 | 变化没那么频繁 |
| 轨迹 | 只在切时间范围时 | 拉 2000 个点不便宜，不该每 5 秒来一次 |

用轮询而不是 WebSocket/SSE：一个用户、一个浏览器标签，
轮询的代价是每 5 秒一个几百字节的请求，而长连接要处理重连、心跳、
以及「服务端重启后前端怎么恢复」。不值得。

## 7. 怎么验的

**没有浏览器自动化** —— 这台机器上 `browser_no_host`。所以：

**服务端侧（30 条，`tests/test_web.py`）**：鉴权边界、cookie 标记、限速、
指令 403、密钥脱敏、配置嵌套解析、key 读取失败的日志。

**前端 JS（16 条，`tests/test_web_frontend.py`，用 `node`）**：
- `node --check` 语法检查 —— 内联 JS 拼错了只在浏览器控制台报，服务端一切正常
- **坐标转换和服务端逐点比对**（7 个点，误差 0 厘米）
- 用**假 DOM + 假 fetch** 跑一遍渲染逻辑，检查每个字段渲染成什么

渲染测试实际跑出来的结果：

```
online     = '在线'              class='badge on'
moving     = '静止'              class='badge off'
lock       = '未知'              class='badge unk'     ← lk=null 的正确显示
pos        = '31.230416, 121.473701'
acc        = '8 米'
src        = '卫星定位'
volt       = '51.5 V'
pct        = '68 %'
gf         = '围栏内'
ls         = '7 分钟前（2026/9/2 00:35:00）'

[motion     ] 检测到移动 260 mg        7 分钟前
[unlock_deny] 开锁被拒 uid=1          9 分钟前
[lock_state ] 锁状态变化（打开）        11 分钟前
[lowbatt    ] 电量低（1 级，46.2 V）    12 分钟前
```

**`lk=null` 显示成「未知」而不是「未上锁」** —— 这是最重要的一条断言，
后者会让人以为车没锁好而白跑一趟（位置反馈微动开关是选配的）。

**容器里也验过**：`docker compose up -d` 之后未登录访问 `/` 给登录页、
登录后给地图页、`/api/config` 返回 32 位 key、设备走 TLS 8883 发 10 个点，
`/api/track` 拿到 10 个点、`/api/state` 有 `gla`/`glo`。

**测不到的**：布局、CSS、地图交互、高德 SDK 的真实行为。
那些要真浏览器 —— 有 browser host 之后可以补。

## 8. 关掉网页

```json
"web": { "enabled": false }
```

关掉之后 `/`、`/ui/*`、`/api/*` 全部 404，JSON API 不受影响。
